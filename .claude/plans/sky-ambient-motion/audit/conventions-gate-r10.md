## Findings

### CONV10-1 (minor): `meteorsAllowed` keeps a shooting-star name and doc after P8 makes it every kind's launch gate

- **Section.** 6.7 (P8's renames), 6.9 ("In the worker (P8)"), P8's and P11's files, 7.0's committed-doc rule.
- **Problem.** P8 renames `SCENE.heroMeteorMaxScroll` to `heroLaunchMaxScroll` "because it then gates every kind", and `SceneLevels.meteors` to `launches`. The worker function that reads `launches`, `meteorsAllowed`, keeps its name: from P8 it is the test the launch gate's `allowed` reads, for every kind, and the sleeping timer's guard. Its doc ("True when a shooting star may launch at all right now (its own timing aside)") stays meteor-only, so from P11 it hides that satellites pass the same gate, and P11's files list no worker change. The same holds for the worker docs P8 already edits for `holdTransients` and `revealTransients`: `reveal`'s ("start the shooting-star clock"), the `motion` case's comment and P4's `noteInput` ("no shooting star straight away"). 7.0's list of docs P11 extends names only `TRANSIENTS`, the envelope's `clearSky`, the spec's `lease` and `drawTransient`.
- **Evidence.**
  - PLAN.md 1714 (both P8 renames and their reason), 2129 (`LaunchGate.allowed`: "the hero scene (SceneLevels.launches)"), 2331 (the gate refilled "from today's `meteorsAllowed`"), 2336 (the sleeping timer "armed only while `meteorsAllowed(now)`, the test the gate's `allowed` reads"), 1628 (`noteInput`'s doc), 3203-3208 (P8's worker files, no rename or doc), 3296-3301 (P11's files, no worker), 2754 (P12: `allowed` keeps only "a launch scene"), 2825 (7.0's P11 list).   - cf4d7b8 `sky.worker.ts:162-165` (the doc and the body reading `sceneAt(...).meteors`), `:183`, `:455` (`reveal`'s doc), `:504` (the `motion` case's comment).
- **Fix.** In P8's worker step, rename `meteorsAllowed` to `launchesAllowed` (after `launches`), documented "True when transients may launch at all right now (each kind's own timing aside)", and word `reveal`'s, the `motion` case's and `noteInput`'s docs for transients as P8 edits those functions; update 6.9's two mentions (2331, 2336) and list the rename in P8's files. ## What passes

- **Code style in all 41 sketches.** Tabs (except the markdown-nested `LEAN_POINTER_QUERY` block); no line-end semicolons; single quotes, with double quotes only on JSX string attributes as in `Navbar.tsx`; no namespace imports, `any`, enums, classes, non-null assertions or `var`; no em or en dash anywhere in `PLAN.md` or `REVIEW-LOG.md` (counted with Node). Import specifier order is not enforced (no Prettier or sort rule in `eslint.config.mjs`), and long lines match the codebase (61 lines over 160 characters in `src`).
- **Imports.** Model files import their siblings by relative path; kind modules import `transients.ts` with a statement-level `import type`, and every mixed import keeps a value specifier; worker files import only `@/lib/sky/*` by file and each other; `mountSky.ts` still takes only types and `@/lib/sky/color` from `src/lib/sky`; `skyPause.ts` reads `@/lib/utils` (`utils.ts:20`) and nothing from `src/lib/sky`; `SkyPauseButton.tsx` imports the `@/components/icons` and `@/lib` barrels as `Navbar.tsx:7-8` does, and `./skyPause` as `SkyCanvas.tsx` imports `./mountSky`. Nothing new is reached from `/links`. No runtime cycle: `transients.ts` imports the kinds' specs, and the kinds import it for types only.
- **Client boundary and components.** `SkyPauseButton` is a default export with a props interface, rendered by the client `Navbar.tsx` (`'use client'` at `Navbar.tsx:1`), so no directive; D1's Server Component hosts give the control's own file the directive and keep `motion/react-client` (`AppFooter.tsx`, `SidePane.tsx`) or the hero's `StaggerItem`, with `data-sky-quiet` and AGENTS.md's quiet-copy precondition kept. The glyphs sit on `Icon` with no `title` (decorative), as default exports with named re-exports in the alphabetical barrel, like `ExternalLinkSVG` and `CalendarSVG`. New file names follow the folder's patterns (`skyPause.ts` beside `mountSky.ts`, `SkyPauseButton.tsx` beside `SkyCanvas.tsx`, camelCase model files).
- **Config docs and names.** Every new config block, key and main-thread constant has a doc in `config.ts`'s style (backticked keys, units stated, sources named as `config.ts` names Mitchell Charity and the Yale catalogue); units follow `config.ts:2-3` (`Ms` names, `stepDevicePx`, `meteorHeightKm`, seconds elsewhere). New names follow the code's patterns (`*At`, `create*`, `step*`, `note*`, `*Wanted`, `*Transients`, `*SVG`) and collide with no name in `src/lib/sky` or the worker at cf4d7b8. Every backticked identifier in the plan exists in cf4d7b8, in a sketch, or is defined in the plan's prose.
- **Probe.** The config blocks and the `camera.ts`, `pacing.ts`, `presence.ts`, `quietIndex.ts`, `gaps.ts`, `transients.ts`, `meteorKind.ts`, `radiants.ts` and `meteors.ts` sketches compile on cf4d7b8 under TypeScript 6.0.3 with the repository's options (the one error is cf4d7b8's `options: PlanOptions = {}` default, which the sketch says P9 drops once `steer` is required) and lint with 0 errors; the 16 warnings are imports read only by bodies the plan declares without sketching.
- **Node 24 and TypeScript 6.0.** `module.registerHooks`, `--disable-warning` and type stripping are Node 24 features (`.nvmrc` 24, `engines.node` 24.x); `typescript` stays `~6.0.3`, and nothing newer than `satisfies` is used; the repository targets ES2020 with `esnext` libs, which covers `Object.fromEntries` and `Math.hypot`.
- **Process.** `npm run lint` and `npm run type-check` for every phase (7.0, and listed in most phases' verification); `/_next/mcp` (`get_errors`, `get_compilation_issues`, `compile_route`) while `next dev` runs on our own `autoPort` server (`.claude/launch.json`); the production smoke build with that server stopped, then `portfolio-prod` (CLAUDE.md); conventional commit forms (`feat(sky)`, `refactor(sky)`, `docs`), as master's `feat(sky)`, `feat:`, `fix:` and `chore:` history; the `motion` docs query before P5's entrance; no `.env` file, no Cache Components API, `data-sky-quiet` kept, the Next.js upgrade reminder handled, and no POST to `/api/schedule/book`.
